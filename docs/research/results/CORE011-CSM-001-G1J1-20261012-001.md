## Frozen physical fixture and cross-process equivalence

The dedicated builder process (PID **3665**) generated deterministic source content in bounded 1-MiB blocks using the G1-I seed, wrote the genuine CSM via the public API and **deleted the source file before launching consumers**. The consumer processes never created the original 384-MiB source array and read only physical CSM metadata. It is a real process boundary, not merely a dropped `WeakReference`.

## Excluded initial pilot — do not conceal invalid provenance

Earlier [run #38267585395](https://github.com/definitely-stable/ChunkShift/actions/runs/38267585395) executed successfully with a real CSM and 5 independent consumer processes; artifact ID `11755322350`, ZIP SHA-256 `216e73ea49db41de6c6880045e66c49124ba83886a7ddf9c2695abb68e56a36f`.

**Excluded from accepted semantic evidence:** the fixture serialized `Hash256.ToString()` for `FileDigest`, producing `ChunkShift.Primitives.Hash256` rather than its actual 64-character hexadecimal digest. A matching type-name string could falsely satisfy that additional cross-process oracle, although the public CSM CRC/ManifestId/full verification still ran and passed.

The flaw was corrected in #309 by using `Hash256.ToHexLower()` on both builder and consumer and by rejecting non-canonical digests in the machine evaluator, with regression mutation tests. The accepted run above was executed **after** this correction. First-run CPU/allocation samples are **not** included in this dataset.

## Interpretation, limits and next gate

**J1 isolated-fixture feasibility PASS only.** This is a single GitHub-hosted runner, fixed deterministic 384-MiB corpus, four workers and only two timed rounds. It does not qualify process CPU or wall throughput differences, GC pause percentiles, idle trimming, pinned private-pool ownership, Windows/AOT, adversarial malformed input, large real-versioned pairs or representative resource envelopes.

The baseline eager, lazy-only control and hybrids 1/2/4 are **not ranked** here. The raw allocation and memory numbers are preserved only as diagnostics of the measurement system, not production decision samples. No product `src/` or defaults have changed.
