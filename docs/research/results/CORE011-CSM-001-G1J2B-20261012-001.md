## Critical interpretation

This is a **real negative result**: two actual CLR DLLs only 512 bytes apart in physical size gave **zero CDC chunk reuse** for this selected commit pair and default profile. No inference is made about all .NET binaries or about patching performance. The output is **NO_GO_NO_MIXED_REUSE**, despite fully correct CSM encoding/verification and Plan execution.

The small base/target CSMs are each one CBLK and do not exercise the large reader array pool. Per-round wall/CPU/allocations are retained solely to audit diagnostic completeness, **not** for comparing eager, lazy or cap1/2/4 and not for choosing a production default. A single runner and two short rounds are not CPU calibration.

**Next research direction:** preregister an independently sourced **large, genuine versioned binary corpus** (e.g. pinned licensed .NET framework / compiler package releases), with verifiable upstream package hashes, original managed DLLs, a positive mix of reused/missing chunks, and ideally a multi-CBLK sample. Do not fabricate reuse via hand-modified DLL bytes, adapt decision budgets to observed outcomes, or treat absence of reuse as a failure of the Plan implementation. Preserve negative cases as robustness controls.
