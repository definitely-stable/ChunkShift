## Evidence interpretation and falsifiability

**Replication:** Independent hosted jobs within each OS consistently observe higher sampled resident high-water in fresh processes holding 16 partially enumerated CSM readers than separate controls. They do not establish an exact causal per-reader cost. Sixteen actively held buffers is not sixteen CPU cores or sixteen concurrently executing tasks. Memory telemetry uses the B1 native sources: Linux Private_Clean + Private_Dirty via smaps_rollup, Windows PSAPI EX2 PrivateWorkingSetSize. No substitution with Linux virtual PrivateMemorySize64.

**Observer effect is substantial on Linux:** Within 30 seconds, the Linux **zero-reader control** itself rises from an initial approximately 13.77 MiB to an observed private resident peak around 30.7–30.8 MiB. The high-frequency in-process smaps/CLR observation, trace construction and runtime phase evolution are materially confounded. The reported peaks MUST NOT replace B1 low-frequency idle snapshots as an uninstrumented process baseline or be taken as a production memory limit. Causation for all the observed Linux control growth has not been isolated. Before memory budget freeze, test sampling disabled versus sampling enabled or use an external native observer / allocation-minimized resident probe.

**Sampling is not a hard high-water certificate:** The maximum is taken over observed 100-ms points and sixteen explicit open checkpoints. A shorter unobserved memory spike can still exceed it, so the result is a **sampled lower bound** on the continuous instantaneous maximum, not a release upper bound. Source builder, windows OS paging, JIT and garbage collection introduce more variance. The previous E3-R2-B1 300-second Windows trimming result still stands independently and is not contradicted by this 30-second measurement.

**Boundaries:** Eager-only synthetic CSM. No lazy/hybrid candidate run, no real versioned pairs, full-product Patch.Plan, SHA256/BIDX variants, Windows AOT/ARM64, long-term post-idle pressure study, or frozen numerical CPU and memory budget. Original 0.1.1 E3 DEFER and R0 preregistration decisionRunsAllowed=false remain intact.

**Disposition:** E3-R2-B2A SAMPLED_BASELINE_CALIBRATION_PASS / PRODUCT_NOT_QUALIFIED / NO_ADOPT. Next E3-R2-B2B should isolate sampling overhead, obtain an external low-perturbation trace on both OS, validate virtual commit vs physical resident vs managed heap across Windows 300s idle, then expand unsealed real-versioned predecision baselines and Plan. Independent R3 sealed decision remains forbidden until a prospective numeric budget freeze.
