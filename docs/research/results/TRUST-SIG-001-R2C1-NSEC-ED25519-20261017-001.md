## Interpretation, adoption boundary

**Research verdict: R2C1_NSEC_OPENSSL_INTEROP_PASS (specialized host proof), subject to final-head repository CI/CodeQL/Heavy/Benchmark signoff.**

A standalone .NET pure Ed25519 client **can** interoperate with an independent OpenSSL 3 signer/verifier and valid DSSE PAE under .NET 10 JIT and NativeAOT on the tested 4-host platform matrix. This closes the last *basic algorithm interop* blind spot from R2A. It does **not** demonstrate minisign/signify framing/comment handling, DSSE JSON envelopes, TUF key/role/rotation metadata, authenticated root bootstrap, trusted time, external high-water cursor, transport/mirror availability, protected private signing keys or secure publication of an installed tree. NSec/library security auditing and native-assets checksum/signature supply-chain validation were not performed; transitive NuGet version presence is not provenance validation.

Architecture: keep **no new production signer** while #185 remains an open threat-model and distribution-layer decision. When a host is already using a mature TUF client, its role and key metadata belong to that update framework; ChunkShift continues to produce content identities. P-256 in the .NET 10 BCL remains the least-dependency verified cryptographic baseline in the R2-A/B1 comparison, whereas Ed25519 via NSec is technically viable **only when the additional libsodium packaging burden is justified**. R2C1 does not supply evidence that another first-party cryptographic package is needed.

Next separate slice if warranted: R2-C2 **actual minisign wire interop** (including trusted/untrusted comments and canonical signature framing), tightly pinned independent CLI and hash-locked dependencies; then an #185 decision RFC on external TUF-only guidance vs optional signing package. Separately, an independently rollback-resistant installed-state high-water/active-tree witness and power-safe T4-C2 publisher must be designed before any public update mechanism is adopted. #184/#185/#251 stay OPEN; public Patching API/release remain BLOCKED.

## Final security hardening and independent second evidence check

Following initial host proof, the R2-C1 .NET code was improved to **never export the NSec signing key**. The NSec key is now created with default non-exportable policy and disposed after use; OpenSSL uses its own isolated ephemeral signer instead of sharing a private key. The driver still creates/deletes an independent OpenSSL PEM under a temporary directory and archives only the four public evidence files.
