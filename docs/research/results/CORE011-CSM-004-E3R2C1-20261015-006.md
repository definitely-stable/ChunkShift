## Meaning of the native resident/CPU measurements

The Linux and Windows absolute private-resident numbers above belong to different machines and cannot be treated as paired perf comparisons or memory acceptance budgets. The external counter source is target-PID Linux `/proc/<pid>/smaps_rollup` Private_Clean+Private_Dirty or Windows cross-process PSAPI EX2 PrivateWorkingSetSize, 100ms polled with 41–42 specifically active `PlanAsync` samples per case. In contrast to E3-R2-C0, the original 28–105ms active-phase aliasing limitation has been resolved for this new control (≥4s active) — **but 100ms maxima remain sampled lower bounds on instantaneous peaks**, and external polling still has OS cost. The target also records active wall/CPU/alloc/GC, but neither single-host values nor varying call counts can qualify a CPU threshold or production noninferiority. No fake statistical significance, observer-cost correction constant, or candidate winner asserted.
