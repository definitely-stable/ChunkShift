## Actual natural idle RSS and retained virtual bytes

Only the 384-MiB / workers 16 cell deliberately observes 300 seconds of **natural, non-forced-GC** idle. Values in MiB (bytes / 2^20):

| Host | WorkingSet at 0s | at 30s | at 300s | Process.PrivateMemorySize64 at 0s | at 300s |
| --- | ---: | ---: | ---: | ---: | ---: |
| r0 | 57.754 | 59.441 | 59.543 | 193.754 | 162.293 |
| r1 | 58.562 | 59.707 | 59.801 | 194.293 | 162.562 |

Natural RSS increased slightly over idle on both machines; this is **not evidence of leaked reader buffers**: CLR heaps, JIT and OS residency all contribute. Conversely, Process.PrivateMemorySize64 drops by roughly 31 MiB while RSS rises. **On Linux this metric must not be treated as actual private resident RSS**, and no production private-RSS/retention budget can be frozen from this data. The separately labelled forced-GC snapshot in each original per-cell JSON is **not** substituted for natural idle. Likewise last-GC LOH size is not interpreted as LOH allocation count.

Although 16 workers were requested, original per-batch maxActiveReaders reached only **4 or 5** for the high-concurrency lanes, on hosts with 4 reported processors. Therefore this is *not* a 16-simultaneously-active-readers memory bound.

## Strong evidence of uncontrolled CPU/runtime phase effects

| Cell | Batch CPU median r0 | Batch CPU median r1 | Qualitative warning |
| --- | ---: | ---: | --- |
| 1 MiB, 1 worker | ~3.08 ms | ~11.60 ms | strong cross-host runtime variance |
| 384 MiB, 16 workers | ~395.58 ms | ~191.53 ms | large opposite CPU disparity |

Within original r1 384-MiB worker-1 eight-round samples, batch wall times include roughly **200 ms initially** and **9–11 ms at the end**, while actual CSM bytes remain pinned. r0 in the analogous workload stays ~25–29 ms. This suggests potentially important JIT/tier/CPU-frequency/runner scheduling phases, **not a demonstrated causal explanation**. Do not use these unstratified medians to set a global CPU regression percentage or prefer cap2. These results reinforce the independent runtime gating concerns preserved in earlier G2-C3/C4 work.
