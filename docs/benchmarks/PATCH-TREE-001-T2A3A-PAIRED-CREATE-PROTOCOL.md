## Frozen A3A decision threshold (research, not shipping SLA)

**Working CPU admission guard:** per-pair T2/T0 median **process CPU ≤3.0×** AND median **wall ≤3.0×**, plus absolute T2 median wall **≤60 seconds** per original tree. All four pairs must pass; if any exceeds, mark `A3A_CREATE_COST_GATE_FAIL__T2_DEFER` for first-release consideration. These numerical thresholds are explicitly preregistered conservative research gates for deciding *whether to invest in A3B*, **not** an existing customer SLA or a promise of real-world speed; they cannot be weakened after seeing original outcomes. Report median ranges and raw samples (not only pass/fail); hosted scheduling noise prevents extrapolation to a shipping environment. The A2 historical 42–68s wall already flags risk but cannot serve as a paired denominator.

If A3A passes all its experimental gates: `A3A_PAIRED_CREATE_FEASIBLE_ONLY__RSS_AND_TRUST_UNQUALIFIED`, then preregister A3B independently: isolate SDK Apply in separate process with bounded actual ChunkId locator, Linux `smaps_rollup` private resident `Private_Clean+Private_Dirty` (document PSS differences), independent sampler A/A, cgroup/observer overhead and source access safety; Windows requires platform-specific validated metric, not Linux label copied over. A3B must include signed source authority / host-owned publication feasibility before adoption.

In *all* cases T2 remains **NO_PRODUCTION_ADOPT**, #184/#251 OPEN, existing T0 release contract unaffected. Four original calibration transitions are **not sealed holdout**. No automatic format/API/publisher changes or first-release promotion, even if CPU passes.
