G1-J2 explored binary reuse and CSP physical size; those results do not quantify CSM CRC/ManifestId/CBLK parsing cost. Do not restart G1-J2K or reclassify the final 0.1.1 decision.

This G2-A slice restores the missing CPU component screen before spending CI on an implementation candidate. It makes **no source, public API, CSM/CSP, default or release changes**.

## Frozen diagnostic setup

- Source is an actual physical CSM v1 generated by the repository's \`CsmEncoderSession\` from deterministic synthetic \`ChunkId/Length\` tuples. No pretend CBLK layout, no original content corpus, no content-verification claim.
- Stable shipped profile and exact registered fingerprint; hash suites BLAKE3-256 / SHA-256; BIDX on/off.
- Entries: 64 (short block) and 4,096 (full CBLK). The latter is 147,500 physical CBLK bytes (16+24+4096*36+4).
- Before any measurement: run the real production \`CsmReader\` metadata verification; require the canonical ManifestId and CRC to match a separately decoded block.
- Benchmarked lanes: **full manifest-only verify**, CRC32C over the original encoded CBLK, per-entry ManifestId accumulation, decode+ManifestId, and decode-only checksum. \`BenchmarkDotNet.MemoryDiagnoser\` records allocations.
- Run under .NET 10 Release on GitHub-hosted runners. Use the existing \`micro\` runner, for example:

\`\`\`bash
dotnet run --project benchmarks/ChunkShift.Benchmarks/ChunkShift.Benchmarks.csproj -c Release -- micro --job short --memory --filter '*Core011CsmComponentBenchmarks*'
\`\`\`

## Interpretation limits / next gate

The component methods **overlap** (decode+hash contains the hash loop, full verify contains CRC, other sections, allocations and reader setup). They are NOT disjoint wall/CPU components, cannot be added into Amdahl percentages, and do not establish an optimizer's end-to-end benefit. BDN method-call/async setup overhead is included in measured full verification. Heap cost and p50/p95 must be compared by the same suite, BIDX and entry count on independent hosted runs. 64 and 4,096-entry synthetic manifests are *diagnostic controls*, not a real multi-CBLK mixed-reuse production corpus.

**Next allowed experiment:** use this screen to select one expensive component, then preregister a matched true end-to-end candidate vs baseline on the same physical CSM and supported platforms. Make a *separate*, reviewed new freeze contract with numeric budgets and decision permissions before any ADOPT. Reuse existing G1-J guard without bypassing its \`decisionRunsAllowed=false\`. A changed backend or data layout must preserve golden bytes, CRC/corrupt-later-block verdicts, early-entry exposure boundary, FileDigest, ManifestId, cancellation and API.

Do not change historical \`CORE011-CSM-001=DEFER\` machine/human index status merely because the G2-A diagnostic code was committed; a future actual RunId and EvidenceId would be separate, and an adopted change would require a new authorized release decision.
