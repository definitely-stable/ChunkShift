# PATCH-INCR-001 A1 — verified source and multi-splice convergence

**Date:** 2026-10-28. **Owner:** [#150](https://github.com/definitely-stable/ChunkShift/issues/150); research freeze [#251](https://github.com/definitely-stable/ChunkShift/issues/251). **Status:** SYNTHETIC LAB / NO_PRODUCTION_ADOPT; no new original performance RunId or release verdict.

## Trust model and deliverable

A0 ([prior protocol](PATCH-INCR-001-A0-SINGLE-SPLICE-PROTOCOL.md)) required an already verified old CSM and a trusted single-splice map without enforcing those assumptions in code. A1 is a separate bounded research oracle that **first snapshots** the source, physical CSM and all replacement arrays, then uses the public `ChunkManifest.VerifyAsync` to verify **all old content against the supplied CSM**, additionally consumes `ManifestReader` to EOF and requires valid final integrity flags. Only the shipped 16/64/256 KiB FastCDC profile and default hash suite are admitted.

A1 constructs new bytes **only** by applying ordered, nonoverlapping replacement operations to the verified old snapshot. Consequently no unreported changes outside the declared edits are possible *in this lab*. Untrusted external dirty hints and a caller-supplied already-mutated target are NOT accepted. This immutable synthetic construction is expensive: reads/copies the **entire old source** for verification, builds the entire new byte array, limits both to 8 MiB, and accepts at most 32 edits. It is not an efficient updater or general file API.

Each edit is the half-open old interval `[OldStart,OldEnd)` replaced with a copied byte array. Edits must be sorted and nonoverlapping, with strictly increasing starts; duplicate-position zero-length insertions are rejected rather than silently reordered. For edit i, `delta_i = sum(replacement.length - removed.length)` and `newEditEnd_i = OldEnd_i + delta_i`. The untouched gaps are mapped by a **piecewise** old-to-new translation. A0's single constant delta is *not* applicable across multiple edits.

## Cut-and-reset convergence algorithm

1. Reuse complete ordered records before the first affected cut and later records in unchanged gaps. Do **not** use a terminal old EOF-only record as a restart cut when appending.
2. At the last genuine reusable cut, reset the **actual** public ChunkScanner and scan new bytes, including edit replacements and any intervening gaps.
3. For each gap after edit i and before edit i+1, build candidate old cuts P at/after edit i's old end and at/before the next edit's old start. Require P to be a **non-EOF recorded old cut**. Candidate new positions are Q=P+delta_i, with Q at/after the mapped new edit end and before new EOF.
4. Only a new scanner-emitted real boundary Q matching such a candidate is proof of resynchronization. After P/Q, reset state is identical (chunk length and Gear hash zero), and the suffix bytes are equal **until the next edit**. Copy that gap's whole original records, mapped by delta_i; then rescan at the next affected cut. If an edit prevents any earlier resync, continue scanning across edits and use a candidate for a later gap. A matching ChunkId without matched cut coordinates is **never** sufficient.
5. After convergence following the last edit, append remaining old suffix records at the corresponding delta. If no mapped real cut exists, full-scan through EOF. Recompute the authoritative `ManifestId` by sequentially appending **all** output (ChunkId,Length) records using original Core accumulator; do not compose cryptographic digests.

**Proof by induction over edit windows:** The initial prefix is identical and ends at a genuine cut. At every accepted Q/P pair, content in the mapped gap is identical, both scanners have reset Gear state, and the already-emitted middle was generated by the real scanner; hence reusing the gap's full old chunk records preserves exact boundaries and IDs until the next edit. Restart at the cut immediately preceding that edit and repeat. If a candidate is not found, scanner continues, so there is no speculative reuse. At the final accepted cut, the whole remaining suffix is identical and can be reused. Thus the ordered result is exactly the full scan for the immutable splice-derived target.

**Coverage / fail-closed:** Tests compare all ordered offsets, lengths and ChunkIds, and independently compare computed ManifestId to `ChunkManifest.CreateAsync` on the complete generated target. They exercise two distant edits with actual interior reuse and new-source read savings; zero/repeated content, old EOF, insert/delete, empty/full-file, 48 deterministic mixed edits, invalid overlapping/unsorted/duplicate edit coordinates, wrong old content, CSM corruption and cancellation.

## Measurement and promotion boundary

A1 `TargetScanBytesRead` counts actual `ReadAsync` bytes of the **new target scanner only** (including read-ahead and possible repeated reads). It **excludes** the unavoidable old-source verification, CSM double-read, target construction, in-memory copies and full CSM oracle. Therefore any observed `TargetScanBytesRead < targetLength` is a *synthetic mechanism demonstration*, not end-to-end wall/I/O savings. There is no production/native RSS claim and no first-release format/public API change.

**Next A2, NOT done here:** pinned snapshot + verified old CSM via bounded stream, source-backed target changes (not full in-memory construction), precise dirty map authority, actual physical CSM v1 writer/reader roundtrip and failure injection. Separately account old verification bytes, new source bytes read/rehashed, old CSM bytes, manifest records rehashed, CSM physical bytes, CPU/wall and peak private resident memory. Real 10/100 GiB product workloads need separately frozen A3 study. #150/#251 remain OPEN; do not label A1 ADOPT.
